Best DPI for Amazon KDP Covers and Interior Images

For a KDP paperback, the DPI that matters is the number of pixels in the file divided by the inches it will occupy on the printed page. Amazon's paperback submission guidelines say all cover and manuscript images should be at least 300 DPI. The same page recommends a maximum of 600 DPI so the upload stays under the 650 MB file cap. Those two figures are the practical range. A higher number in the file's properties dialog is not, by itself, a better print.

KDP's separate page on formatting images describes 300 DPI as the resolution that produces the best print quality, says there is no set maximum, and warns that excessively high resolutions can make processing time out or delay manufacturing. The upload limit stated there is also 650 MB. Read the two pages together: aim for at least 300 DPI at the placed size, and treat 600 DPI as the ceiling KDP itself suggests when file size is the constraint. KDP defines a low-resolution image as anything under 200 DPI.

DPI is pixels per printed inch

A monitor can look sharp at a small pixel grid because the image is only a few inches of glass. A printed page is larger, and the press lays down a fixed pattern of dots. If you place a 600-pixel-wide picture across a 6-inch text block, the print gets 100 pixels for each inch. That is 100 DPI, which is under KDP's low-resolution line of 200 DPI and well under the 300 DPI minimum.

pixels needed = print size in inches × target DPI
effective DPI = pixels ÷ print size in inches

The multiplication is exact, so the examples below are arithmetic rather than a house style. Round a fractional pixel up. A file that is half a pixel short of the minimum is still short.

A full-trim pixel count is only the right target when the image actually bleeds to the trim, or when you are sizing the page itself. An interior photo almost always sits inside the margins, so it needs fewer pixels than the full page.

Interior images and the margin table

KDP's paperback guidelines set the minimum inside (gutter) margin from the page count, and they set the outside margin to at least 0.25 inches with no bleed, or at least 0.375 inches with bleed:

151–3000.5 in (12.7 mm)at least 0.25 inat least 0.375 in

501–7000.75 in (19.1 mm)at least 0.25 inat least 0.375 in
701–8280.875 in (22.3 mm)at least 0.25 inat least 0.375 in

Take a 6 × 9 inch book of 151 to 300 pages, no bleed, using those minimums. The text block is 6 − 0.5 − 0.25 = 5.25 inches wide and 9 − 0.25 − 0.25 = 8.5 inches tall. An image that fills that block at 300 DPI needs 5.25 × 300 = 1,575 pixels across and 8.5 × 300 = 2,550 pixels down. Wider margins, which many templates use, shrink the block and lower the pixel requirement. Measure the width you actually assign in the layout, then multiply. Do not enlarge the picture after you insert it. KDP's image guide says enlargement lowers the resolution, because the same pixels are spread over more inches.

If the image bleeds off the page, the interior PDF has to be a PDF, and the page is larger than the trim: 0.125 inches wider and 0.25 inches taller than the trim size. A 6 × 9 inch bleed page is 6.125 × 9.25 inches, which is 1,838 × 2,775 pixels at 300 DPI after rounding the half pixel up. Bleed extends past the top, bottom, and outer edge only. It does not cross the gutter.

Covers use the same 300 DPI floor

A paperback cover is one continuous image: back cover, spine, front cover, plus 0.125 inches of bleed on every side. The pixel target is the full wrap in inches times 300, not the front cover alone. Spine width changes with page count and paper. The cover size guide walks through KDP's spine formulas. A Kindle ebook cover is a different specification, measured in pixels rather than print DPI. That file is covered in the Kindle cover guide. Do not reuse a 1,600 × 2,560 ebook JPEG as a paperback wrap.

The DPI label is not the pixel grid

KDP's image help says that manually changing the DPI reading can make a file report 300 DPI without increasing quality, because that edit does not add pixels. Their wording is that it is not possible to add dots by altering the tag. If a properties panel says 300 DPI and the picture still looks soft in the previewer, either the tag was edited or the photograph was already out of focus. Check pixels divided by placed inches. That is the resolution KDP is describing.

The upscaler on this site does a different operation. It resamples the bitmap to a larger width and height. New pixels are interpolated from neighbors. The canvas is drawn with image smoothing on and smoothing quality set to high. That can bring a short file up to the pixel count a 300 DPI placement needs. It does not recover texture, focus, or small type that was never in the file. The download also does not write a DPI metadata tag. After you save it, the properties panel may still say 72 DPI or 96 DPI, or it may show no density at all. Judge the file by its pixel dimensions.

Use the tool only after you know the gap. Effective DPI = pixels ÷ inches. If that number is already 300 or more at the size you will print, leave the file alone. If it is short, set Source DPI to the effective DPI and Target DPI to 300.

Open the upscaler

A worked case: a JPEG is 900 pixels wide and you will print it 5 inches wide. Effective DPI is 900 ÷ 5 = 180, which is under 200, so KDP would call it low resolution. Set source to 180 and target to 300. The scale is 300 ÷ 180 = 1.666…, and 900 × 1.666… = 1,500 pixels, which is 5 × 300. Setting source to 72 and target to 300 instead would scale by 300 ÷ 72 = 4.166… and produce a 3,750-pixel-wide file. That file is larger than the placement needs, and it is still no sharper than the 900-pixel original in any detail the original did not contain.

What to prepare before you export

  • Decide the placed size in inches, including bleed if the image runs off the page.
  • Multiply each side by 300. That is the minimum pixel size. Use 600 only when the subject is fine line work and the PDF still has room under 650 MB. See 300 vs 600 DPI.
  • Compare those pixels with the file you have. Upscale only the shortfall.
  • Insert the image at the size you calculated. Do not drag the corner handles past that size.
  • Flatten layers and transparency before you make the print PDF. KDP says transparent areas can print as a different color than the surrounding ink.
  • Order a proof if the image is a cover or a page the book depends on. The on-screen preview is not the printed sheet.
