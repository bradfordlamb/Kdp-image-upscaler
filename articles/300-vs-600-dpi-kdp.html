300 vs 600 DPI for KDP: Which Should You Use?

Use 300 DPI as the working resolution for KDP print photos and ordinary interior art. Use 600 DPI when the image is line art, a map, a diagram, or type converted to outlines, and only if the finished PDF stays comfortably under KDP's 650 MB upload limit. That split follows the paperback submission guidelines: every cover and manuscript image should be at least 300 DPI, and KDP recommends a maximum of 600 DPI specifically to keep the file under 650 MB.

The image-formatting page is slightly different in tone. It says images at 300 DPI produce the best print quality, that higher DPI shows more detail, and that there is no set maximum, while warning that excessively high resolutions can time out during processing or delay manufacturing. Neither page says a 600 DPI photograph will look twice as sharp as a clean 300 DPI photograph of the same scene. Doubling the DPI doubles each side of the pixel grid and multiplies the pixel count by four. The file gets heavier. Detail appears only if those extra pixels contain real information.

A JPEG of a photograph compresses that growth, so the file does not always become four times larger on disk. A PNG of a map, or a PDF that embeds several uncompressed images, often does grow sharply. A paperback interior and its cover are separate uploads, and each one is limited to 650 MB. A book that is already near that cap does not have room to move every figure from 300 to 600.

Where 300 DPI is the right stop

Continuous-tone images — photographs, paintings, soft illustrations — are the case KDP's image page is describing when it says 300 DPI produces the best print quality. At a normal reading distance, a clean 300 DPI photo does not show its pixels. Going to 600 DPI stores a finer grid. If you created the file at 600 DPI from a high-resolution camera or scan, keep it, as long as the PDF uploads. If you only have a 300 DPI original, resampling it to 600 DPI invents the in-between pixels. The print can look slightly smoother along hard edges and still look soft in the detail, because the detail was not captured.

KDP also tells you not to enlarge an image after you insert it. A 300 DPI file that you then stretch to twice the size becomes a 150 DPI file at the new size. That is under the 200 DPI line KDP calls low resolution. The fix is to calculate the placed inches first, not to crank a DPI menu after the fact.

Where 600 DPI earns the file size

Line art, hairlines, maps, sheet music, cross-hatching, and text that has been turned into pixels benefit from a finer grid. A 1-pixel stair-step that is acceptable in a photograph is a jag on a letter or a coastline. KDP's interior rules also set a minimum line weight of 0.75 point, which is 0.01 inch (0.3 mm), for rules, charts, and graphic elements. A line that thin is only 3 pixels tall at 300 DPI (0.01 × 300) and 6 pixels tall at 600 DPI. The extra samples give the rasterizer something to anti-alias. Build that art at 600 DPI in the drawing program if you can. Upscaling a 72 DPI screenshot of a map to 600 DPI will not reconstruct the labels.

Paperback covers follow the same minimum of 300 DPI across the whole wrap, including spine and bleed. A cover that is mostly a photograph is a 300 DPI job. A cover built from thin rules and small type converted to outlines is a reasonable 600 DPI job, provided the PDF is still a sane size. Flatten the cover to one layer before you export. KDP asks for that on both the submission guidelines and the image page, because leftover transparency can print as a patch of different color.

What this site's tool will do if you type 600

The upscaler does not inspect the picture and decide. It divides the target DPI by the source DPI and multiplies both pixel sides by that ratio. Source 300 and target 600 exactly doubles the width and the height. Source 72 and target 600 multiplies by 600 ÷ 72 = 8.333…, which turns a modest screen graphic into a very large canvas. Browsers refuse canvases past an internal size limit, and the download can fail with no file. The resizer guide describes that behavior in the order the script actually runs.

Set the source field to the image's effective DPI at the print size you intend, not to a guess of 72, unless the image really is a 72 DPI screen graphic that you will print at its current physical size. Effective DPI is pixels divided by inches. If a 2,400-pixel-wide photo will be 8 inches wide, it is already 300 DPI. Sending it through a 300-to-600 pass makes a 4,800-pixel file that is four times the pixels and no more in-focus than the original.

Choose 300 DPI unless the art is fine line work you generated at high resolution, or you are correcting a file that is under 300 DPI at the placed size. Choose 600 DPI for that line work when the PDF can spare the bytes. Do not choose 600 DPI as a rescue for a tiny, soft, or heavily compressed original.

A decision you can apply to one file

  1. Write down the placed width and height in inches. Use the wrap size for a cover, not the front panel alone. The cover calculator guide has the formula.
  2. Divide the pixel width by the inch width. Do the same for height. The lower of the two numbers is the effective DPI.
  3. If both sides are at least 300, stop. Export a high-quality JPEG for a photo or a PNG for line art, and flatten transparency.
  4. If a side is under 300 and you have a better original, use the better original. KDP's own advice for raising quality is to reshoot, buy a print-resolution stock file, or print the image smaller.
  5. If you must resample, scale only to 300 DPI for photographs. Scale line art toward 600 DPI only when the enlarged pixel count is still something your browser and your PDF can hold.

The print previewer in KDP will still warn on images it measures as low resolution. A warning on a file you have already checked at 300 DPI of placed size usually means the layout stretched the image, the DPI tag and the pixels disagree, or the picture is full-bleed and you measured the trim instead of the bleed box. Recalculate before you resample again.
