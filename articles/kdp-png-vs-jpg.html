PNG vs JPG for KDP: Which Format Is Better?

Use PNG for KDP images that contain text, line art, flat color, or hard edges. Use a single high-quality JPEG for photographs. KDP accepts both inside a print file, and the choice matters because JPEG throws away information on every save while PNG does not. The paperback guidelines do not declare a winner between them. They do say images should be at least 300 DPI, transparency should be flattened, and each upload must be 650 MB or smaller. Those three rules decide the awkward cases.

What each format keeps

PNG compression is lossless. Open a PNG, save it again, and the pixels match. That is why type, icons, screenshots, diagrams, and illustrations with flat fills stay crisp. The files are larger. A full-page PNG at 300 DPI is a heavy object in a PDF, and a book full of them can approach the 650 MB cap. KDP also recommends you not take images past 600 DPI, for the same cap.

JPEG compression is lossy. It stores photographs efficiently because photographs are smooth gradients rather than single-pixel lines. At a high quality setting the damage is small. At a low setting you get halos around type and blocks in the sky, and those blocks print. Saving the same JPEG five times at a medium setting is worse than saving it once, because each save quantizes again. Keep a master that is not JPEG — a camera raw file, a TIFF, or a PNG — and write the print JPEG at the end.

Transparency is a print problem, not a format trophy

KDP's image page says transparent areas can print a slightly different color from the surrounding ink, and the cure they give is to flatten layers in the final file. For cover art they want one flattened image at 300 DPI. A PNG that uses transparency to knock out a background is exactly the case they are warning about. Flatten it onto the paper color or the real background before you export the print PDF. JPEG forces that flatten, because it cannot store the alpha channel. That is an advantage for a cover that should have been flattened anyway, and a reason not to use JPEG if you still need the transparent master for editing. Keep the layered master for yourself. Where KDP names formats directly

Interior manuscripts are PDF when anything bleeds. When nothing bleeds they may be PDF, DOC, DOCX, RTF, HTML, or TXT, and KDP converts them. The images inside are whatever those containers embed. PNG and JPEG both embed. TIFF is a common prepress format, and nothing on the paperback image pages forbids it inside a PDF, but this site's tool does not export TIFF. If a workflow you already trust writes TIFF at 300 DPI with no extra compression, you do not need to route it through this tool.

A custom paperback cover is a PDF, one continuous image, flattened. Cover Creator, Amazon's in-browser cover tool, accepts JPG, PNG, and GIF. GIF is a poor cover format: it is limited to 256 colors. Prefer PNG or a high-quality JPEG there too.

Kindle marketing covers are specified on two different help pages. The cover-criteria page lists TIFF and JPEG. The cover-guidelines page lists JPEG, PNG, non-animated GIF, and TIFF, and it calls JPEG the preferred format. SVG is not supported. Both pages cap the file at 50 MB, which is a different cap from the 650 MB print cap. The Kindle cover guide lays out the pixel size and the places those two pages disagree. A print-wrap PDF is the wrong file for that slot. The ebook image is the front cover only.

What this site's tool can export

The upscaler writes PNG or JPEG and nothing else. The Format menu is those two choices. Quality percent defaults to 95. That number is divided by 100 and handed to the JPEG encoder. It has no effect on PNG. The canvas is drawn with smoothing quality set to high, at a scale of target DPI ÷ source DPI. The download's name ends in the target DPI.

Choose PNG in that menu when you are resampling line art or text. Choose JPEG when you are resampling a photograph, and leave quality at 95. Do not resample a JPEG, open the result, and resample it again. Go back to the master if the first scale was wrong. The tool also does not write a DPI tag. A PNG or JPEG from the canvas can still report 72 DPI in a file browser while holding a 300 DPI pixel grid for your placed size. Divide pixels by inches before you conclude the export failed. The resizer guide documents that behavior.

Pick the format for the content, then resample only if the pixel count is short. A format change does not add resolution.

A few files that look like edge cases

  • A screenshot of a web page that you want in a chapter: PNG, sized so the placed inches × 300 is within the pixel count, or print it smaller. JPEG will ring around the text.
  • A color photograph on a black-ink book: it will print in black and white even if the interior option is color, unless the photo itself is color and you selected color ink. The format does not change that. KDP states it on the image page.
  • A logo with a soft drop shadow on transparent stock: flatten onto the cover background, then PNG if the logo has small type, or JPEG if the cover is mostly photography and the logo is simple.
  • An image you have already saved as JPEG three times and now want as PNG: the conversion stops further damage and does not repair the damage already there. Return to the earliest file you still have.

Line weight still applies after you pick a format. Graphic rules in the book need to be at least 0.75 point (0.01 inch). A one-pixel line in a 72 DPI PNG becomes a faint scratch when that PNG is placed several inches wide. Fix the pixels, not just the extension. The DPI guide is the pixel arithmetic.
